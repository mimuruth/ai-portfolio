## Engineering Lab 2 — A reproducible environment you can trust

### The mental model

Think of a virtual environment as a **sealed workshop**. Each project gets its own
workshop with its own labelled tools (package versions). Two projects that need
different versions of the same tool never collide, and when you write down exactly
which tools are on the bench (`pyproject.toml`, `.python-version`), anyone can
rebuild the identical workshop and get the identical result.

### First-principles logic — why pinning matters

A benchmark is a function of *many* inputs: hardware, model weights, and every
library version in the stack. Write it as

$$\text{result}=f(\text{hardware},\ \text{model},\ v_1, v_2, \dots, v_k)$$

If any $$v_i$$ changes silently, `result` can change and you cannot attribute the
difference. Pinning fixes every $$v_i$$, turning an irreproducible observation into
a controlled measurement. This is the same discipline as a lab notebook.

### Bare-metal implementation — a portable health check

No framework — just the standard library — to prove the environment is wired up:

```python
import sys, shutil, urllib.request, json

def check():
    print("python:", sys.version.split()[0])
    print("ollama on PATH:", bool(shutil.which("ollama")))
    print("docker on PATH:", bool(shutil.which("docker")))
    try:
        with urllib.request.urlopen("http://localhost:11434/api/tags", timeout=2) as r:
            models = [m["name"] for m in json.load(r).get("models", [])]
        print("ollama models:", models or "(none pulled yet)")
    except Exception as e:
        print("ollama server: not reachable ->", type(e).__name__)

check()
```

> **EXAMPLE — output on a ready machine.**
> ```
> python: 3.14.4
> ollama on PATH: True
> docker on PATH: True
> ollama models: ['llama3.2:latest', 'phi4-mini:latest', 'mistral:latest']
> ```

> **Production note — the CUDA wheel trap.** `prod-rag`, `local-slm-lab`, and
> `realtime-voice` install cleanly from PyPI. `llm-finetuning` pulls the deep-
> learning stack, whose wheels track your GPU driver — install PyTorch from the
> **CUDA index** that matches your driver (`--index-url .../cu121`), never the
> default CPU wheel, or training silently falls back to the CPU and takes days.
