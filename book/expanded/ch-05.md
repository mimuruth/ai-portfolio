## Engineering Lab 5 — Percentiles, cost, and the metrics rollup

### The mental model

A **trace** is a **flight recorder** for one request: it shows exactly how long the
request spent in each stage (retrieve, rerank, generate) as a stack of timed
**spans**. **Metrics** are the **airport statistics** across all flights: how many
requests, how fast at the median and the tail, how much each cost. You need both —
the recorder to debug one bad request, the statistics to see the system's health.

### Mathematical formulations

**Percentiles.** Sort the $$N$$ latencies ascending, $$x_{(1)}\le\dots\le x_{(N)}$$.
The $$p$$-th percentile is the value at rank $$\lceil (p/100)\,N\rceil$$:

$$P_p=x_{(\lceil (p/100)\,N\rceil)}.$$

The **p90** means "90% of requests were at least this fast." One 12-second request
hidden behind a hundred fast ones vanishes in a **mean** but stands out at p90 —
and it is exactly the user who churns.

**Cost.** With $$t_{\text{in}}$$ input and $$t_{\text{out}}$$ output tokens and per-
million prices $$c_{\text{in}},c_{\text{out}}$$:

$$\text{cost}=\frac{t_{\text{in}}}{10^6}\,c_{\text{in}}+\frac{t_{\text{out}}}{10^6}\,c_{\text{out}}.$$

For `gpt-4o-mini` ($$c_{\text{in}}=0.15,\ c_{\text{out}}=0.60$$) a tightly-reranked
RAG answer lands at the **measured $0.00025 / request**.

### Bare-metal implementation — the rollup in standard library

This is the essence of `rag.observability.metrics`, reading the per-request JSONL
the pipeline writes:

```python
import json, math

def percentile(values, p):
    if not values:
        return float("nan")
    s = sorted(values)
    idx = max(0, math.ceil(p / 100 * len(s)) - 1)
    return s[idx]

def rollup(path):
    lat, cost, cited, errors = [], [], 0, 0
    n = 0
    for line in open(path, encoding="utf-8"):
        r = json.loads(line)
        n += 1
        lat.append(r["latency_ms"])
        cost.append(r["cost_usd"])
        cited += 1 if r.get("citations") else 0
        errors += 1 if r.get("error") else 0
    return {
        "p50_ms": percentile(lat, 50), "p90_ms": percentile(lat, 90),
        "avg_cost": sum(cost) / n, "citation_cov": cited / n, "failure_rate": errors / n,
    }
```

> **EXAMPLE — over 8 grounded queries (the MEASURED rollup).**
> ```
> {'p50_ms': 2326, 'p90_ms': 3709, 'avg_cost': 0.00025,
>  'citation_cov': 1.0, 'failure_rate': 0.0}
> ```

> **Production note — report p95/p99 only with volume.** With $$N=8$$, the p95 and
> p99 land on a single sample and are pure noise. Report p50/p90 at small $$N$$ and
> add the tail percentiles once you have hundreds of requests — the rollup already
> supports them.
