## Engineering Lab 10 — Shipping a container the boring, reliable way

### The mental model

A container is a **shipping container**: the same sealed box loads onto a truck,
a ship, or a crane (laptop, cloud, Kubernetes) and its contents behave identically.
An **immutable tag** (`:1.0.0`) is the box's serial number — you deploy a serial
number, and rolling back is just pointing at the previous one.

### First-principles logic — cost at scale, and rollback

From the **measured** unit cost $$c=\$0.00025$$ per request, daily spend at request
rate $$n$$ is simply

$$\text{daily} = n\cdot c,\qquad \text{monthly} \approx 30\,n\,c.$$

At $$n=10{,}000$$/day: $$\$2.50$$/day $$\approx \$75$$/month in model spend (an
**ESTIMATE** — it extrapolates the measured per-request cost). Because deployments
reference an immutable image tag, **rollback** is $$O(1)$$: repoint from `:1.0.0` to
`:0.9.0`. Never deploy `:latest` to production — it is a moving target you cannot
roll back to.

### Bare-metal implementation — a readiness probe

What a platform's health check effectively does, standard library only:

```python
import urllib.request, sys

def ready(url="http://localhost:8000/healthz", timeout=2):
    try:
        with urllib.request.urlopen(url, timeout=timeout) as r:
            return r.status == 200
    except Exception:
        return False

sys.exit(0 if ready() else 1)   # non-zero => platform withholds traffic
```

`prod-rag`'s container builds its index on first boot, then serves `GET /healthz`
and `POST /ask`; the platform routes traffic only once readiness passes.

> **EXAMPLE — one-command publish + deploy.**
> ```
> git tag -a v1.0.0 -m "..."; git push origin v1.0.0   # CI builds + pushes image
> az containerapp up --image ghcr.io/mimuruth/prod-rag:1.0.0 \
>   --ingress external --target-port 8000 --env-vars OPENAI_API_KEY=secretref:openai-key
> ```

> **Production note — secrets never live in the image.** Inject `OPENAI_API_KEY`
> and `LANGFUSE_*` as platform secrets at runtime. Baking a key into a layer ships
> it to everyone who can pull the image — treat any such key as compromised (Ch. 3).

### Review & exercises

- **Troubleshooting.** After a deploy, some instances 500 on the first request.
  Which probe is misconfigured, and how does the index-on-boot design relate?
- **Computation.** At $$c=\$0.00025$$/request and 250,000 requests/day, estimate
  monthly model spend. Which single change would most reduce it?
- **System design.** The voice service holds long-lived WebSocket connections. Why
  is a scale-to-zero serverless-function target a poor fit, and what would you pick?
