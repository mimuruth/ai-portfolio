## Engineering Lab 7 — Low-rank adaptation and preference tuning, by the numbers

### The mental model

The base model is a **printed reference manual** you are not allowed to reprint
(the weights are frozen). **LoRA** is a pad of **sticky notes**: for each page you
add a thin correction that the reader applies on top. You train only the sticky
notes — kilobytes — not the whole book. **QLoRA** additionally photocopies the
manual at lower resolution (4-bit) so it fits on a smaller desk (GPU), while still
writing full-quality sticky notes. **DPO** is showing the model **pairs** — "this
answer is better than that one" — and nudging it toward the preferred one.

### Mathematical formulations

**LoRA.** A frozen weight matrix $$W\in\mathbb{R}^{d\times k}$$ is adapted by a
low-rank update built from two small matrices $$B\in\mathbb{R}^{d\times r}$$ and
$$A\in\mathbb{R}^{r\times k}$$ with rank $$r\ll\min(d,k)$$:

$$W' = W + \frac{\alpha}{r}\,B A.$$

Only $$A$$ and $$B$$ are trained, so the **trainable parameters** drop from
$$d\,k$$ to $$r(d+k)$$. The saving ratio is

$$\frac{r(d+k)}{d\,k}.$$

For $$d=k=4096,\ r=8$$ that is $$\dfrac{8(8192)}{16{,}777{,}216}\approx 0.0039$$ —
about **0.4%** of the parameters trained per layer.

**QLoRA memory.** Storing the base at 4 bits costs $$\approx 0.5$$ bytes per
parameter, so a $$P$$-parameter model needs roughly

$$\text{VRAM}_{\text{base}} \approx 0.5\,P \text{ bytes}.$$

A 4B model $$\Rightarrow \approx 2\text{ GB}$$ for weights; add optimizer state and
activations for the tiny adapter and it fits comfortably in a 16 GB GPU — which is
why a 4B model is tunable on a single consumer card.

**DPO.** With policy $$\pi_\theta$$, frozen reference $$\pi_{\text{ref}}$$, and a
preference pair (prompt $$x$$, chosen $$y_w$$, rejected $$y_l$$):

$$\mathcal{L}_{\text{DPO}}=-\log\sigma\!\left(\beta\left[\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)}-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\right]\right).$$

Minimising it **increases the log-probability margin** the policy assigns to the
chosen answer over the rejected one, relative to the reference — no separate reward
model required.

### Bare-metal implementation — parameter accounting

You do not need a GPU to *understand* the saving. Pure Python:

```python
def lora_params(d, k, r):
    full = d * k
    lora = r * (d + k)
    return full, lora, lora / full

for r in (4, 8, 16, 64):
    full, lora, ratio = lora_params(4096, 4096, r)
    print(f"r={r:>3}: full={full:,}  lora={lora:,}  trained={ratio:.4%}")

def qlora_gb(num_params_billion, bits=4):
    return num_params_billion * 1e9 * (bits / 8) / 1e9   # GB for weights

print("Qwen3-4B @4-bit weights ~", round(qlora_gb(4), 2), "GB")
```
